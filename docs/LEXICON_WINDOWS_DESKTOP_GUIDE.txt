ĐỊNH HƯỚNG ỨNG DỤNG DESKTOP LEXICON TRÊN WINDOWS
================================================

Mục đích
--------
Lexicon là từ điển cá nhân. Người học bắt gặp từ ở nơi khác, lưu lại ngữ cảnh và ghi chú, sau đó ôn tập ngoại tuyến.

Kiến trúc được chọn
-------------------
Vỏ desktop: Tauri 2
Giao diện: React + TypeScript + Vite
Cơ sở dữ liệu cục bộ: SQLite thông qua plugin Tauri SQL
Lớp máy chủ/đám mây: NestJS + Prisma, tùy chọn cho đồng bộ và hỗ trợ nhiều thiết bị về sau

Vì sao chọn Tauri
-----------------
Tauri phù hợp với ứng dụng Windows vì nhẹ hơn Electron và không cần đóng gói toàn bộ runtime Chromium/Node. Frontend React hiện tại có thể dùng lại. NestJS vẫn hữu ích như API đám mây trong tương lai, nhưng ứng dụng desktop không nên mãi phụ thuộc vào một tiến trình NestJS chạy trên localhost.

Trạng thái hiện tại của kho mã nguồn
------------------------------------
- frontend/: ứng dụng React/Vite.
- frontend/src-tauri/: bộ khung desktop Tauri 2.
- backend/: API NestJS với Prisma và SQLite.
- backend/prisma/schema.prisma: schema lưu từ vựng và lịch ôn tập.
- backend/prisma/dev.db: cơ sở dữ liệu phát triển do Prisma tạo.
- backend/data/words.json: file seed/đầu vào cũ; không dùng làm nguồn sản phẩm chính.
- docs/: tài liệu lộ trình sản phẩm và hướng dẫn Windows này.

Những phần đã hoạt động
-----------------------
- CRUD từ vựng qua NestJS.
- Phát hiện mục từ trùng.
- Metadata từ vựng: lemma, cặp ngôn ngữ, từ loại, CEFR, sense và mục tiêu học.
- SQLite và migration Prisma.
- Bảng ReviewState và ReviewHistory.
- Bộ lập lịch ôn tập đơn giản.
- API ôn tập: /reviews/due, /reviews/states, /reviews/:wordId và lịch sử.
- Vỏ Tauri với plugin SQLite và script build desktop.
- Adapter lưu trữ frontend: SQLite cục bộ trong Tauri, HTTP NestJS trên web.
- CRUD từ vựng và thao tác ôn tập cục bộ đi qua adapter này.

Hạn chế quan trọng hiện tại
---------------------------
Phiên bản dễ dùng đầu tiên vẫn là bản web cục bộ. Vỏ Tauri và adapter lưu trữ đã có, đồng thời bộ cài NSIS đã được build trên máy phát triển. Việc cài và chạy lần đầu trên máy sạch vẫn cần kiểm tra.

Chế độ phát triển web tiếp tục dùng HTTP NestJS. Khi phát triển web, chạy backend riêng:

  cd backend
  npm run start:prod

Sau đó chạy vỏ desktop từ terminal khác:

  cd frontend
  npm run desktop:dev

CRUD và ôn tập desktop đã dùng adapter SQLite cục bộ. Lần chạy đầu tạo các bảng cục bộ nhưng không tạo từ mẫu. Có thể nhập và xuất mục từ dưới dạng JSON Lexicon; lịch sử và lịch ôn chưa nằm trong file chuyển đổi. Sao lưu/khôi phục và kiểm thử trên máy sạch vẫn cần hoàn thiện.

Kiến trúc sản phẩm mục tiêu
---------------------------

  Giao diện React
      |
      v
  Dịch vụ ứng dụng TypeScript
      |
      +-- Adapter desktop: lệnh Tauri / SQLite cục bộ
      |
      +-- Adapter web: API HTTP NestJS (tùy chọn)

Vị trí cơ sở dữ liệu sản phẩm trên Windows:

  %APPDATA%\Lexicon\Lexicon.sqlite

Không lưu dữ liệu người dùng trong Program Files hoặc bên cạnh file thực thi. Cơ sở dữ liệu phải tồn tại qua các lần cập nhật và không yêu cầu quyền quản trị.

Mô hình cơ sở dữ liệu cục bộ mục tiêu
-------------------------------------
Schema Prisma hiện tại là schema máy chủ/đám mây. Schema SQLite desktop về sau nên có các khái niệm cốt lõi tương tự:

- vocabulary_entries
- senses
- examples
- tags
- collections
- review_states
- review_history
- settings

Không nhân đôi một mục từ chỉ vì nó thuộc nhiều collection. Không đặt lịch ôn bên trong component React.

Thứ tự triển khai
-----------------
1. Sử dụng và ổn định chế độ web cục bộ V1.
2. Thêm migration schema lần đầu và seed/nhập tùy chọn cho Tauri.
3. Lưu bản sao lưu rõ ràng trong thư mục dữ liệu người dùng.
4. Thêm nhập và xuất JSON/CSV.
5. Kiểm thử file Tauri trên máy Windows sạch.
6. Giữ NestJS là lớp API/đồng bộ tùy chọn.

Lệnh phát triển
---------------
Backend:
  cd backend
  npm run db:status
  npm run db:migrate
  npm run build
  npm run start:dev

Frontend web:
  cd frontend
  npm run dev
  npm run build

Phát triển desktop Tauri:
  cd frontend
  npm run desktop:dev

Biên dịch Tauri không tạo bộ cài:
  cd frontend
  npm run desktop:build

Tạo bộ cài NSIS Windows:
  cd frontend
  npm run desktop:installer

Điều kiện cần trên Windows
--------------------------
- Node.js LTS
- Rust stable với bộ công cụ MSVC
- Microsoft C++ Build Tools
- WebView2 Runtime
- Windows SDK

Nếu Rust không tìm thấy `link.exe`, cài Visual Studio Build Tools 2022 với:

  Desktop development with C++
  MSVC v143 build tools
  Windows 10/11 SDK

Sau đó mở PowerShell mới và chạy:

  cd frontend
  npm run desktop:build

Nếu Cargo vẫn không tìm thấy `link.exe`, chạy build từ "x64 Native Tools Command Prompt for VS 2022" hoặc mở PowerShell từ cửa sổ dành cho nhà phát triển đó.

Quy tắc an toàn dữ liệu
-----------------------
- Không commit file .env hoặc file cơ sở dữ liệu SQLite.
- Chạy migration trước khi mở ứng dụng.
- Sao lưu cơ sở dữ liệu trước migration có khả năng phá hủy dữ liệu.
- Phải giữ khả năng xuất JSON/CSV kể cả khi thêm đồng bộ đám mây.
- AI và API từ điển là tùy chọn, không được chặn việc học từ cục bộ.

Tiêu chí hoàn thành ứng dụng Windows độc lập
--------------------------------------------
- Mở Lexicon từ một shortcut của bộ cài.
- Không cần terminal.
- Các chức năng từ vựng và ôn tập cốt lõi không cần tiến trình NestJS.
- Dữ liệu tồn tại sau khi khởi động lại và cập nhật ứng dụng.
- Tìm kiếm, xem chi tiết, thêm, sửa, xóa và ôn tập hoạt động ngoại tuyến.
- Nhập/xuất và sao lưu/khôi phục đã được kiểm thử.
- Có thể cài và chạy trên một máy Windows sạch.

Hướng dẫn cho trợ lý AI về sau
------------------------------
Không tùy tiện viết lại dự án hoặc thay stack. Trước tiên đọc file này, lộ trình sản phẩm và các file package hiện tại. Giữ React/Vite cho giao diện và dùng Tauri cho vỏ Windows. Giữ NestJS/Prisma làm lớp máy chủ/đồng bộ trừ khi task yêu cầu chuyển chức năng sang cơ sở dữ liệu Tauri cục bộ. Ưu tiên migration nhỏ, build sau mỗi mốc và báo rõ hạn chế còn lại thay vì coi ứng dụng desktop đã hoàn toàn ngoại tuyến.
